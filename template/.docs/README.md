# Документация проекта

> Четыре слоя документации — память для ИИ-агента. Агент читает их сверху вниз перед каждой задачей.

## Структура

```
.docs/
├── 0-context/              # Якорь: зачем продукт существует и что есть сейчас
│   ├── vision.md           # Зачем проект и что уже построено
│   ├── assumptions.md      # Предположения и ограничения
│   └── system-state.md     # Текущее состояние системы
│
├── 01-product/             # Истина: единое описание продукта
│   └── prd.md              # Один документ, а не десять
│
├── 02-features/            # Фичи: папка на задачу
│   └── <имя-фичи>/
│       ├── feature-spec.md # Что хотим
│       ├── tech-design.md  # Как строим
│       ├── dev-tasks.md    # Задачи для агента
│       └── test-plan.md    # Как проверяем
│
├── 03-logs/                # Логи: дневник проекта
│   ├── decisions-log.md    # Решения и почему
│   ├── implementation-log.md # Что построено и когда
│   ├── bug-log.md          # Баги и их причины
│   ├── validation-log.md   # Что произошло после запуска
│   └── insights.md         # Выводы
│
├── 04-process/             # Процесс (необязательно)
│   ├── dev-workflow.md     # Как работать с документацией
│   ├── definition-of-done.md # Когда работа считается готовой
│   └── llm-prompts.md      # Готовые промпты для агента
│
└── README.md               # Этот файл
```

## Два правила

1. **Якорь и Истина обновляются.** В `0-context/` и `01-product/` всегда один актуальный документ. Старое переписывается, а не копится рядом.
2. **Логи дописываются.** В `03-logs/` ничего не стирается. Новая запись идёт в начало файла, под заголовок.

## Как агент пользуется документацией

1. Перед задачей читает `0-context/`, потом `01-product/prd.md`, потом папку нужной фичи.
2. Работает по `dev-tasks.md` и проверяет себя по `test-plan.md`.
3. После работы пишет в `03-logs/`: что сделал, какие решения принял, какие баги нашёл.
4. Если изменилось состояние системы — обновляет `0-context/system-state.md`.

## Новая фича

Скопируй папку `02-features/_feature-template/` под именем фичи (например, `02-features/payments/`) и заполни сначала `feature-spec.md`.

## Частые вопросы

**Когда обновлять system-state.md?** После каждого заметного изменения: новый сервис, запуск, переезд.

**Как часто писать в логи?** В конце каждой рабочей сессии хотя бы одну строку в `implementation-log.md`.

**Что делать, если документ устарел?** Исправить сразу. Устаревшая документация хуже, чем никакой: агент ей поверит.
