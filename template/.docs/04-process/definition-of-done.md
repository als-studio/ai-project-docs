# Когда работа считается готовой

> Общие критерии готовности для задач, фич и документов.

## Задача

- [ ] Выполнены все пункты «Готово, когда» из `dev-tasks.md`
- [ ] Работает локально
- [ ] Тест или ручная проверка прошли
- [ ] Нет «TODO» без записи, когда это доделать
- [ ] Статус задачи обновлён
- [ ] Запись в `implementation-log.md` сделана

## Фича

- [ ] Выполнены все критерии из `feature-spec.md`
- [ ] Все задачи из `dev-tasks.md` готовы
- [ ] Все проверки из `test-plan.md` прошли
- [ ] Строка фичи в `prd.md` обновлена
- [ ] `system-state.md` отражает новое состояние

## Документы

| Документ | Готов, когда есть |
|----------|-------------------|
| vision.md | Цель, что есть сейчас, чего не делаем |
| assumptions.md | Ограничения, проверенные и непроверенные предположения |
| system-state.md | Схема и актуальные статусы компонентов |
| prd.md | Пользователи, сценарии, список возможностей с приоритетами |
| feature-spec.md | Намерение, критерии, граничные случаи |
| tech-design.md | Устройство, данные, интерфейсы, риски |
| dev-tasks.md | Атомарные задачи с критериями готовности |
| test-plan.md | Проверка на каждый критерий |
| записи в логах | Дата, что произошло, почему, что дальше |

## Проверка качества документации

- [ ] Даты свежие
- [ ] Документы не противоречат друг другу
- [ ] Ссылки работают
- [ ] Решения объясняют «почему», а не только «что»
- [ ] В документах нет паролей, ключей и токенов
