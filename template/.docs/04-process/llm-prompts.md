# Готовые промпты

> Короткие промпты, которые можно вставить в агента. Квадратные скобки заменить своим текстом.

## Начать сессию

```
Прочитай .docs/0-context/, .docs/01-product/prd.md и свежие записи в .docs/03-logs/.
Кратко расскажи: что за проект, что сделано в прошлый раз, какие баги открыты.
Потом жди задачу.
```

## Новая фича

```
Создай папку .docs/02-features/[имя]/ по образцу .docs/02-features/_feature-template/.
Заполни feature-spec.md. Намерение пользователя: [кто, что, зачем].
Задай мне вопросы про граничные случаи, прежде чем писать критерии.
```

## Как строим

```
Прочитай .docs/02-features/[фича]/feature-spec.md и .docs/0-context/assumptions.md.
Напиши tech-design.md: устройство, данные, интерфейсы, риски.
Предложи два варианта для ключевого выбора и порекомендуй один.
Принятое решение запиши в .docs/03-logs/decisions-log.md.
```

## Разбить на задачи

```
По feature-spec.md и tech-design.md фичи [фича] заполни dev-tasks.md.
Каждая задача — на одну сессию, с пунктами «Готово, когда» и списком файлов.
Отдельно заполни test-plan.md: проверка на каждый критерий.
```

## Выполнить задачу

```
Выполни задачу [номер] из .docs/02-features/[фича]/dev-tasks.md.
Перед работой прочитай feature-spec.md и tech-design.md.
После работы: поставь статус ✅ и допиши запись в .docs/03-logs/implementation-log.md.
```

## Записать баг

```
Допиши в начало .docs/03-logs/bug-log.md запись по шаблону.
Что случилось: [описание]. Найди корневую причину, а не симптом.
После исправления добавь проверку в test-plan.md фичи.
```

## Закрыть сессию

```
Подведи итог сессии в .docs/03-logs/:
что сделано (implementation-log), какие решения приняли (decisions-log),
какие баги нашли (bug-log), что поняли (insights).
Если изменилась система — обнови .docs/0-context/system-state.md.
```

## Проверить документацию

```
Проверь .docs/ на противоречия:
- все ли возможности из prd.md имеют папку в 02-features или статус «в планах»;
- не противоречит ли tech-design ограничениям из assumptions.md;
- соответствует ли system-state.md тому, что реально есть в коде.
Выдай список расхождений, ничего не исправляй без моего согласия.
```

## Перевести существующий проект

```
У проекта уже есть код, но нет .docs/. Изучи код, README и настройки.
Предложи черновики vision.md, assumptions.md и system-state.md.
Отметь, что ты знаешь точно из кода, а что предполагаешь. Спроси меня о неясном.
```
