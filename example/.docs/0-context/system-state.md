## Схема

```
┌─────────────┐     ┌──────────────────┐     ┌──────────────┐
│   Клиент    │────▶│  Бот (aiogram)   │────▶│ SQLite:      │
│ в Telegram  │◀────│  + планировщик   │◀────│ bot.db       │
└─────────────┘     └──────────────────┘     └──────────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │ Общий чат        │
                    │ мастеров         │
                    └──────────────────┘
```

## Окружения

### Рабочее

- **Где запущено:** VPS, сервис `barber-bot` (systemd)
- **Статус:** ✅ Работает с 30.10.2026, пока в тестовом режиме для 10 постоянных клиентов
- **Последний запуск:** 30.10.2026
- **Известные проблемы:** нет

### Локально

- **Как запустить:** `python -m bot`
- **Что нужно:** Python 3.12, файл `.env` с переменными `BOT_TOKEN`, `MASTERS_CHAT_ID`, `SHOP_TZ=Europe/Moscow` (значения — только в `.env`, не в коде и не в документах)

## Данные

- **Где хранятся:** `data/bot.db`
- **Объём:** 3 мастера, 6 услуг, 14 записей
- **Резервные копии:** раз в сутки копия файла базы в отдельную папку на том же сервере

## Внешние сервисы

| Сервис | Зачем | Что будет, если упадёт |
|--------|-------|------------------------|
| Telegram Bot API | Весь бот | Запись недоступна; клиенты пишут владельцу как раньше |

## Технический долг

| Что | Насколько важно | Чем мешает | Когда чиним |
|-----|-----------------|------------|-------------|
| Расписание мастеров зашито в `config.py` | Средне | Владелец не может сам поставить выходной | Вместе с панелью владельца |
| Резервная копия лежит на том же сервере | Средне | Если сервер умрёт, пропадёт и копия | До полного запуска |
